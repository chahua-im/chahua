# 产品需求与边界

本文是交互要求的统一入口。只描述当前约定，不记录改动过程。具体尺寸见[外观](appearance.md)，请求与一致性见[数据流](data-flow.md)，字段归属见[组件](components.md)，等待状态见[加载与操作反馈](loading-indicators.md)。

## 范围

- 使用现有后端协议，不为前端展示新增接口或修改后端行为。生成的服务、模型不手动改名。
- 保留 `chats`、`conversations`、`messages` 三个关注范围；组件、局部工具与共享状态按实际职责划分，不为每个接口创建服务。
- Snowflake ID 的无损 number 编码是性能选择。可选字段允许运行时 `null`，不全量转换为 undefined；两处清除字段的特殊语义见[API 边界](data-flow.md#身份协议与入口)。
- 不提供 OOBE/欢迎引导、主动添加群成员、多语言切换，也不为其他功能增加设置项。`/landing` 是安装页，保留旧版五个平台的安装指引、文案和样式；已安装应用直接进入聊天或邀请预览。
- 所有路由静态导入；表情选择器、媒体编解码等非路由资源可以按需加载。

## 启动、布局和导航

- 登录同时保存 localStorage 和 Cookie，兼顾长期保留与安装时传递；读取顺序、续期与失效处理见[身份数据流](data-flow.md#身份协议与入口)。URL token 读取后从地址栏移除。真实 token 不提交仓库，生产构建不注入开发预设。
- Angular 挂载前与登录期间的 spinner 外观一致，不带文字，不出现启动后不存在的“茶话” toolbar。
- `md`（768px）起显示 384px 聊天列表侧栏；`xl`（1200px）起可显示右侧 360px 信息栏。较小屏幕以信息按钮打开 modal；两种信息容器均没有 toolbar。
- 单列进入/返回会话、归档和好友请求历史使用 Ionic 默认 iOS 页面动画与返回按钮。返回无历史时落到对应列表；Safari 已提供可视返回动画时避免重复播放。
- 点击 tab 使用 Ionic 原生 segment 指示器与内容切换动画，只有下方内容移动，toolbar 不飞入。内容区禁止左右手势切换，保留列表项自身的左右滑动操作。四个 tab 各自保留滚动位置，仅当前 tab 激活列表分页查询，tab 计数共享汇总查询。
- 分栏时切 tab、归档和请求历史只改变左侧选择，不改变右侧会话路由或关闭会话。
- 点击头像直接打开设置，没有头像下拉菜单。设置地址显示 `/settings` 并增加历史记录，浏览器右滑/返回只关闭设置，不触发底层列表导航。
- 手机页面禁止浏览器双击、双指缩放，媒体查看器保留自身的图片缩放。
- iOS 键盘弹出、收起或改变高度时，由浏览器处理可见区域和输入框避让；应用不按键盘高度主动缩小或平移根页面。消息区继续使用原生滚动，不通过全局禁止 touchmove 或反复写入 scrollTop 纠正页面。
- 字号和控件密度按操作系统区分，不按是否有触屏或 hover 能力区分；窗口宽度只决定分栏。手机和平板系统使用移动密度，Windows 接触屏仍使用桌面密度。

## 聊天列表

消息与话题 tab 显示后端统计的未读会话数；消息 tab 按“在消息中显示话题”选项包含话题数。群组、好友 tab 暂无分类统计接口，不用已加载分页推算总数。

| 场景                             | 分页与呈现规则                                                             |
| -------------------------------- | -------------------------------------------------------------------------- |
| 消息 tab，开启“在消息中显示话题” | 对话与话题分开请求，只显示两边共同覆盖的时间范围，触底补覆盖较浅的一侧     |
| 消息 tab，关闭该选项             | 只依赖普通对话分页                                                         |
| 群组、好友、话题独立 tab         | 独立分页，不做跨来源时间截断                                               |
| 初次显示或切分类                 | 等当前分类所需列表查询齐备后统一显示行，不能先露出部分缓存行再插入另一来源 |
| 刷新已有列表                     | 保留原内容，刷新结果齐备后替换                                             |
| 已归档、好友请求历史入口         | 常驻且立即可用，历史内容进入时读取；独立计数不阻塞列表                     |

- ChatList、成员及其他 IonList 的末项不显示底部分隔线，分隔线只用于区分列表项。
- 群组/好友的归档计数直接显示后端归档对话未读总数，不遍历归档历史按类型 count。“已归档”的角标为灰色。
- 归档计数与好友请求加载失败时静默保留已有数据，不显示错误行或专用重试按钮，等待下次正常更新。
- 请求历史包含除 pending 外的请求，包括 archive、accept、reject；入口不依赖历史是否为空或读取成功。
- 预览中的作者与系统行为使用主题蓝色，用户正文统一灰色；系统消息整条为蓝色。提及直接消费消息中的名字，显示不等待额外用户查询。
- 草稿在保存时参与排序，不随每次输入重排列表；不为未加载的聊天凭空创建草稿行。
- 日期按本地日历和地区格式显示：当天及跨午夜不足 8 小时用 HH:mm，前 1–6 天用短星期，365 天内其他日期用地区月日格式，更早用 shortDate。不使用 time-ago 或每行计时器。
- 加号菜单包含搜索入口；开启后 toolbar 变搜索条。协议支持群/用户目录搜索，不将它称为全局历史消息搜索。
- 实时连接未就绪时，用 spinner 替换加号图标，原按钮仍然可点。会话 toolbar 有自己的连接指示，不增加底部横条加载标识。

## 会话阅读与滚动

- 从群消息的回复入口进入话题后，返回群聊复用原消息及头像节点、保留滚动位置；不先清空列表再重新加载。
- 普通聊天没有未读时进入最新位置；较长未读区间定位未读边界并显示“未读消息”，短尾部可直接贴底。话题缺读状态时以根消息为起点。显式消息链接、引用与置顶优先定位目标。
- 未读分隔线以进入页面时的已读位置为边界，只落在他人发出的已确认消息前；不随阅读进度移动，撤回后移到下一条符合条件的消息。
- 下箭头在离开最新位置或存在引用返回点时出现，优先返回引用来源，再回到最新。未读数使用共享读状态；不实现协议不支持的未读表态心形导航。
- 普通 DOM 双向分页；接近边缘预取，触摸和惯性结束后合并历史。以可见消息底部为锚，不用每帧写 scrollTop 的循环纠偏。
- 顶部历史加载与 spinner 是同一控件，不配文字。可分页时保留固定尺寸，避免 spinner 插入/移除改变滚动区域；具体交互见[加载反馈](loading-indicators.md)。
- 图片、视频、贴纸、邀请卡片和语音在资源完成前预留尺寸；引用摘要单行省略，不因名字或媒体晚到而改变高度。
- 消息和置顶独立读取，不能用“先置顶、后消息”的串行加载保证稳定。唯一一条置顶的新增/删除会改变栏位高度，因此等待手指松开且惯性结束再显示/隐藏；已有置顶栏内的内容更新立即显示。
- 置顶栏变化后，最新区间保持贴底，历史阅读保持消息屏幕位置。浮动日期与底部按钮保留 DOM 节点，显隐不重建滚动内容。浮动日期与正文日期相交时避让，同一天不重复显示；停止滚动后保留 1 秒，再用 200ms 向上淡出。
- Ionic 缓存页面完成离开时停止读取和滚动处理、释放未提交媒体资源；群聊被其话题覆盖时保留区间与节点，其余会话释放连续区间。应用级草稿和待发队列仍保留。
- 重连只做有限补读，不遍历历史补齐所有编辑、撤回、表态。一致性以旧版可用程度为边界，不引入完整同步日志或离线消息数据库。

## 消息外观与操作

- 同一天、同一作者的连续消息紧凑分组，系统消息打断分组；作者信息在组首，头像与尾巴在组尾。“显示全部头像”偏好仍有效，头像显隐不改变组内间距。
- 消息内只有头像打开发送者资料，用户名行不打开；正文中的提及保留自己的资料入口。
- 用户名与气泡引用的作者色沿用旧版明暗调色板及**用户名 hash**。这与 UID 不同，改名可以改变颜色；用户组颜色来自后端。用户组行高为 1.4。
- 气泡引用为两行：作者半粗、正文常规，作者色竖边与浅背景，正文省略。字号小于正文，不与回复输入栏共用高度。
- 回复输入栏第一行显示“正在回复 xxx”；灰底、正文置灰，用户名及普通竖线为 primary 色，不使用用户色。上下两部分高度一致；竖线与 iOS 输入光标起点对齐，右侧 × 与下方贴纸图标对齐。
- 桌面仅整行 hover 时显示回复按钮；移动系统左滑显示右侧回复图标，相对气泡竖直居中，不计表态高度，随拉动填充，到阈值放大。纵向滚动不触发回复。
- 长按/右键打开表态和 actions，操作网格每行最多 5 项，不足 5 项时按实际按钮数量收窄，行数随可用操作数量变化，不预留空行。预览及面板不因权限或置顶读取晚到而先展示错位布局。消息预览、表态条和操作面板之外的空白均可点击关闭，包括三块内容之间及两侧的透明区域。撤回动作使用红色。
- 菜单中的消息固定显示用户名、气泡尖角和头像，不沿用连续发言的省略状态，不允许滚动预览。补出用户名时向上展开，保持正文原位。消息横向位置与宽度保持不变，表态与操作面板各自避让屏幕左右边缘。三块内容高度能放下时，仅为避开上下边缘平滑移动；放不下时消息正文保持原位，两块菜单靠近点按位置显示，底层聊天滚动位置不变。
- 表态独立显示在消息主体下方，消息头像和桌面回复按钮与气泡底部对齐，不随表态区域下移；表态包含用户头像，胶囊造型与 main 分支一致，可查看完整名单并按表情切换；最近表情跨会话保存。添加或取消表态时，本地立即更新数量、个人选择和自己的头像；个人资料取自当前 SessionStore，后续广播更新服务端统计与头像名单。
- 撤回消息从活消息列表直接移除，不留“消息已删除”行。
- 本人资料不只在登录时使用：后续 HTTP/WS 中的最新本人资料更新共享身份，待发消息的用户组、名字、性别、头像随之更新；收藏快照不反向覆盖当前身份。

## 输入、草稿与待发队列

- 输入框外左侧为圆圈加号，下方面板只有照片、文件两种；输入框内右侧为贴纸按钮，下方展开贴纸面板；输入框外右侧为录音或发送按钮。输入垂直居中，飞机图标向右作小幅视觉偏移。
- Windows 贴纸按钮 hover 提示 `Emoji: Win + .`，macOS 提示 `Emoji: fn + E`。
- 桌面 Enter 发送、Shift+Enter 换行；移动系统 Enter 换行。IME 组字期间不发送，提及候选的 Enter 优先选择候选；空输入向上编辑上一条自己的文字消息，Esc 取消回复或未改动的编辑。
- 可拖入、粘贴附件并选择提及。文件拖入输入栏时高亮可放置区域，拖过内部控件不闪烁；移出、取消或放下后恢复，普通文字拖动不触发附件高亮。不因为消息读取、发送、编辑请求或附件上传而禁用输入；不发送空内容。已知私聊不可发送时，点击提交说明原因并保留文字、附件、录音；关系未知时由服务器判断。
- 离开/切换会话、切后台、pagehide 时保存文本、回复 ID 和时间；不边输入边写草稿。相同内容不重复保存，空草稿删除。编辑文本独立于普通草稿。
- 提交入队即清空对应输入与草稿，迟到确认不能清除后续输入。文件、语音、贴纸独立发送时保留其他未提交内容。

| 队列情形             | 必须保留的行为                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| 点击发送             | 立即上屏，排在已存在消息后；保留稳定 clientGeneratedId，确认回声更新同一行                       |
| 同一会话连续发送     | 准备好的消息串行发出并等待确认，避免顺序倒置；不同聊天/话题独立                                  |
| 附件压缩或上传中     | 可以立即提交并移交任务，附件在气泡上继续显示 progress spinner；不占发送槽，不阻塞后续聊天        |
| 附件失败             | 提交前禁用发送；入队后任一附件失败立即标记整条失败，重试整条时一起重试失败附件并复用已成功附件   |
| 附件准备完成         | 进入普通发送流程，可以像文字一样等待前一条确认、阻塞后一条提交                                   |
| 刚提交就编辑         | 未发请求直接改待发内容；已发请求先取得服务器 ID，再提交编辑。取消编辑不取消队列借出的上传任务    |
| 刚提交就撤回         | 立即隐藏并停止创建重试；未发请求直接移除，已发请求保留撤回意图，取得 ID 后补撤回                 |
| 请求失败             | 显示失败图标，后续消息继续；断网恢复/重连可重试，创建重试保持原 clientGeneratedId 和已发请求内容 |
| 上传取消             | 撤回或移除附件取消处理/上传、释放文件和本地 URL；浏览器不可取消的编码完成后丢弃结果，不继续上传  |
| 语音已确认但尚未发布 | 保留确认与本地播放；转码期间 GET 404 不重新创建消息                                              |

发送状态位于时间之后：`cloud-upload-outline` 上传，`time-outline` 排队/发送，`checkmark-outline` 服务器确认，`alert-circle-outline` 失败。确认勾不带圆圈。

队列只在本次应用内存中跨页面存活，整页刷新/关闭不恢复。协议不能按 clientGeneratedId 查找或撤回：不判断确认是否“彻底丢失”，用户撤回时就隐藏；之后靠正常读取、推送或迟到回包尽力取得 ID，不扫描历史兜底。

## 媒体与录音

- 照片方式发送图片/视频时采用旧版压缩规则，文件方式保留原字节。保护动图，必要时解码 HEIC；无法有效压缩时回退原文件，参数见[媒体数据流](data-flow.md#媒体与语音)。
- 附件选择后即可开始处理；发送后任务归队列所有。录音保存先留本地 Blob，明确发送才上传。
- 支持录音（包括待授权）显示 `mic-outline`，不支持显示 `mic-off-outline`；两者都可点，不支持时显示 IonAlert。录音期间通过录音操作区保存、发送或取消，不同时提交普通文本。
- 语音使用 WaveSurfer.js 波形播放器，包含圆形播放/暂停、波形拖动、时长与倍速，不使用原生音频控制条。点击才加载音频，同时只播放一条；波形读取失败不妨碍可用播放。
- 媒体打开为全屏遮罩，顶部不留空横条，右上控制浮动。底部 gallery 只切换**同一消息**的图片/视频；支持捏合、滚轮缩放、放大拖动、方向键与浏览器全屏。
- 贴纸面板支持收藏、订阅、创建包、向自己的包上传图片/WebM，不新增设置入口。

## 信息、群组、好友与搜索

- 信息头部复用列表头像和话题角标，头像、标题居中，标题最多三行；群简介、用户组和话题所属聊天显示在标题下的小字区域，不显示 UID。右上角关闭按钮为 44px 点击区域、28px 图标。会话 toolbar 的标题左侧显示 32px 头像。
- 群信息显示搜索、静音、退群；管理员额外显示独立邀请按钮，没有更多菜单。话题只显示搜索和订阅/归档，没有更多、群编辑、邀请、退群或聊天收藏入口。静音时显示时长，永久只显示“永久”。
- 群管理员可在名称和简介旁点击铅笔，在原位置编辑现有文字，点击对勾仅保存该字段；名称不能为空，简介可清空。保存失败显示 toast 并保留输入，切换会话丢弃未保存的编辑。头像显示相机角标，点击选择图片，上传时头像内显示进度环，成功后更新。普通成员仅查看资料；不提供群可见性编辑。
- 用户资料弹窗与私聊侧栏共用 ChatDetails，无 toolbar。按钮依次为个人空间、添加好友（非好友）或发消息（好友且不是当前会话的信息面板）、搜索、静音、解除好友（好友）、拉黑/解除拉黑。当前会话的信息 modal 同样隐藏发消息；自己的资料仅显示个人空间。没有可访问会话 ID 时搜索、静音不可用。添加好友的验证方式在点击后读取，确认弹窗内填写验证信息。
- 话题信息区显示“xxx 中的话题”，订阅与归档共用一个按钮：未订阅显示空心星及“订阅”，已订阅显示空心归档及“归档”，已归档显示实心归档及“已归档”，点击取消归档。操作及状态刷新期间保留已知状态文字，不将暂时缺失的状态当成未订阅；不显示退群或删除好友按钮。
- 基础资料已有缓存时立即显示；详情、好友关系或媒体请求不能让整个信息头部变成 spinner。
- 信息标签依次为话题、成员、图片、视频、文件；普通私聊没有成员，话题没有话题标签。打开会话默认第一页，只有选中标签加载。话题成员显示参与者：优先使用话题列表缓存中的完整名单，并合并已加载回复；没有缓存时仅从话题根与已加载消息提取，明确标注范围，不扫描历史或显示所属群成员。图片、视频、文件按所属聊天查询，现有接口不能单独限定话题。
- 搜索与静音入口位于会话标题栏，资料页不显示这两个操作；话题保留订阅/归档按钮，不显示静音。个人资料按钮单行排列，群邀请排在退群前面。
- 信息头部保留背景色区域的留白；标签上方没有额外白色间隔块或标题。
- 成员页没有搜索条和右侧互动按钮，点击行打开资料，右侧只有管理员显示“管理员”。
- 群成员、媒体和聊天搜索使用与 ChatList 相同的 Ionic 无限滚动。话题从普通消息页筛选根消息，游标来自原响应；一页没有话题不意味着结束，也不能为了填满首屏循环扫描历史。加载控件不可点击。
- 话题会话标题与列表预览一致；右侧未订阅显示空心星，已订阅提供归档/取消归档（空心/实心归档图标）。不恢复列表话题的三头像预览。
- 置顶在会话 toolbar 下方显示预览栏，点击定位并轮换，另有完整置顶列表。主 toolbar 底边始终存在。置顶共享活消息，收藏保存快照；两类页面复用 Message 样式，不把静态集合强塞进 ConversationPage。收藏仅保留全局入口，不提供本聊天收藏或其专用路由。
- 保留创建/加入群、编辑群资料、邀请管理、好友申请/接受/拒绝/归档、删除/拉黑、用户资料和论坛链接。权限决定可用操作；邀请预览不自动入群。
- 聊天内全文搜索支持相关度/最新排序；媒体汇总按图片/视频/文件分类，定位消息时进入其所属话题。全局历史搜索、按发送者/日期筛选、独立全量群话题列表无协议支持，不增加客户端全量扫描。

## 通知、静音与设置

- 在线 WebSocket 优先处理通知，页面未运行时由 Web Push 兜底。前后台页面均交给 Worker 展示系统通知；推送注册失败不阻止已经获得授权的在线提醒。
- 支持通知且启用 Worker 的环境，登录进入应用且本机没有通知选择时，显示标题 `允许“茶话”发送通知吗`、说明 `以后可以在设置内修改` 的 Ionic alert。不允许立即关闭并记住选择；允许按钮显示 spinner，授权和推送注册成功后关闭，失败显示“授权失败，请再试一次”的 toast 并保留弹窗供重试。
- 通知设置同步读取环境、本机 `chahua.notifications.enabled` 和浏览器权限。不支持时不继续检查；本机关闭时不请求授权。点击头像进入设置且本机已开启、权限尚未决定时，在点击事件内请求权限；直接访问设置不自动请求权限，缺授权就保存为关闭。
- 已授权且本机开启时，异步确保浏览器订阅与后端登记；后台检查不显示 spinner、不禁用开关，失败静默等待下一次检查。注册失败但权限仍在时保留开启选择；用户主动操作才显示等待和失败反馈；等待时 spinner 替换通知 toggle，权限被拒绝使用 toast，不在设置行内显示拒绝文案。关闭立即停止本机提醒，并尽力删除后端登记、取消浏览器订阅。
- 各平台、各分栏布局统一使用系统通知，需要本机开启通知并获得浏览器授权。正在前台阅读对应会话不提醒；设置或 modal 覆盖会话时仍提醒。
- 通知规则遵循现有协议：自己、系统和已撤回消息不提醒；提及、回复自己、聊天归档、话题订阅/归档的优先关系见[通知数据流](data-flow.md#通知与静音)。通知点击复用应用并定位消息，不能重载丢失待发队列。
- 去重、已读清理和撤回清理使用有界状态与通知中心，不另建消息数据库。系统角标、后台标题使用后端完整未读总数，不重复叠加话题/静音/归档数。
- 静音提供 1 小时、8 小时、1 天、7 天、永久；到期自动更新标志。取消静音按现有协议同时取消归档，不增加跨设备静音/已读轮询。
- 设置为大头像和居中名字；各列表项有图标。消息通知只有一行，不支持时右侧显示“不支持”而非开关；检查更新只有一行，不支持置灰，前面留间隔。没有退出登录按钮。检查更新行显示完整构建版本，与 API 请求携带的版本一致。
- 深浅色均适配，toolbar 背景延伸至系统顶部。原生悬浮滚动条可用时保持原生，否则使用 OverlayScrollbars，不占内容宽度。
