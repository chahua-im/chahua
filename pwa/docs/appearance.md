# 外观与样式边界

Ionic iOS 模式负责 toolbar、列表、按钮、modal、popover、segment 和 spinner。应用统一定义文字层级与信息密度，组件 CSS 负责聊天特有的形状与布局；同类控件共用主题颜色。

## 导航动画

单列的会话进入和返回使用 Ionic 默认 iOS 页面动画。会话页面直接包含 `ion-header`、`ion-content` 和 `ion-footer`，标题栏（含仅显示箭头的返回按钮）与正文分别由 Ionic 默认转场处理；分栏切换会话不播放页面动画。Safari 已提供可视返回转场时，Ionic 只完成页面显示状态清理。

聊天列表保留 Ionic `ion-segment` 的选中指示器。内容区使用浏览器 Web Animations，只让当前分类与目标分类按方向横移一页宽，时长 200ms；中间分类不参与。快速切换取消上一段动画，减少动态效果时直接切换。内容区不提供左右手势，toolbar 保持固定。四个分类常驻，各自保留滚动位置，只有当前分类激活读取和续页。归档与好友请求历史使用独立列表内容和 Ionic 返回按钮；单列保留分类路由和浏览器历史，分栏切分类不改变右侧会话。

会话的消息与置顶独立加载。置顶数据即时更新；置顶栏的出现与消失等待手指松开且惯性滚动结束，期间多次变更只展示最终状态。已显示的置顶栏更新内容无需等待。消息区与可视区域的尺寸由 ResizeObserver 监听：最新区间在底部时保持贴底；阅读历史时按可视区域顶部的位移补偿滚动，使置顶栏出现或消失时消息保持原屏幕位置。仅输入栏高度改变时，历史阅读位置保持不变。监听不在每次滚动中运行，不使用定时补滚动。悬浮日期和右下角按钮保持节点常驻，只切换可见性，滚动开始与结束不增删内容槽节点。右下角按钮在首次定位及滚动位置测量完成后才决定显隐，避免数据到达时短暂闪现。

iOS 根布局保留 Ionic 默认 body 样式，不根据 VisualViewport 的 resize/scroll 改写 body 高度、顶部偏移或底部安全区，键盘避让交给浏览器处理；页面缩放规则见[启动、布局和导航](requirements.md#启动布局和导航)。移动端会话 header 按 VisualViewport.offsetTop 向下平移，抵消浏览器为输入框平移可见区域的位移，标题、置顶栏和语音播放条一起保持吸顶；键盘收起后随偏移归零恢复原位，不改变消息区布局尺寸。历史阅读补偿只计算应用容器内的顶部变化。消息菜单仍按可见视口定位。

## 字体与密度

`src/styles.scss` 集中定义正文、列表标题、预览、紧凑文字、辅助文字和资料标题。组件使用这些角色，不自行判断平台。Ionic 的 `plt-ios`、`plt-android` 选择移动端尺寸，其余操作系统使用桌面尺寸；iPadOS 与 iOS 相同，Windows 接入触屏仍使用桌面尺寸。窗口宽度只决定单栏、双栏和三栏布局。

保留 Ionic 的根字号：桌面浏览器与 Android 默认 16px，iOS 使用系统 Body，默认 17px。文字角色采用 rem，根字号与正文不是同一个概念。移动端按各系统的默认根字号换算，使默认字号和行高为整数，同时保留根字号变化时的文字缩放。下表为默认设置下的实际 CSS px。

| 内容                         | iPhone / iPad | Android | 桌面    |
| ---------------------------- | ------------- | ------- | ------- |
| 消息正文、普通列表项、表单   | 17 / 22       | 16 / 22 | 14 / 20 |
| 聊天列表标题                 | 16 / 22       | 16 / 22 | 14 / 20 |
| 列表预览、资料描述           | 15 / 20       | 15 / 20 | 13 / 18 |
| 消息作者、气泡引用、置顶预览 | 14 / 17       | 14 / 17 | 13 / 17 |
| 列表时间、辅助说明           | 13 / 17       | 13 / 17 | 12 / 16 |
| 消息时间、发送状态           | 11 / 14       | 11 / 14 | 11 / 14 |
| 资料标题                     | 22 / 28       | 22 / 28 | 20 / 26 |
| 聊天列表最小行高 / 头像      | 60 / 52       | 60 / 52 | 60 / 48 |
| 普通列表最小行高             | 44            | 44      | 40      |
| 输入与发送控件高度           | 40            | 40      | 36      |

聊天列表按标题、预览两行布局，最小行高统一为 60px，文字区上下外边距为 6px。

字号、行高与控件密度分别选择，头像、按钮和边距不按正文比例整体缩放。显式指定的资料头像保持 88px，消息头像保持 34px。聊天头像的占位字号、角标尺寸和偏移随头像缩放，并取最近的整数 CSS px。文字头像统一通过 AvatarTextPipe 按完整 Unicode 字素截取，保留 emoji、肤色、组合符号及非 BMP 汉字；消息头像取前两个，其余头像和角标取第一个。媒体占位和右侧 360px 信息栏保持稳定。信息栏各标签的无限滚动控件空闲时仅留 1px 触底检测高度，加载时使用 Ionic 默认 spinner 区域，末页后不占空间。资料区上下留白为移动端 32px/24px、桌面 24px/20px；横排操作最小高度为 64px/56px，长标签可以换行。

普通会话标题的头像右侧使用垂直容器，名称独立使用 600 字重，状态独立使用 400 字重和 caption 字号；资料状态同样使用正常字重。状态行最小高度为一个 `--app-line-caption`，文字单行省略；加载线框放在该行内部，不改变容器高度。在线文字与私聊列表头像右下角的在线圆点共用 `--app-online-color`（`#4DC920`），浅色和深色模式一致。圆点直径为 12px（含 2px 边框），边框跟随列表背景，选中行跟随 primary 背景；圆点不影响头像或列表行尺寸。

资料区横排操作使用 Ionic clear 按钮与主题色浅底：普通操作背景为 primary 的 8%，hover/focused 为 12%，按下为 16%；破坏性操作使用 danger 的 10%/14%/18%。悬停时图标及文字变为对应 shade 色，颜色过渡为 160ms；侧栏与详情弹窗共用。

输入框上方的编辑、转发与回复预览条共用关闭按钮样式：图标使用 `--ion-text-color-step-250` 中性色，随明暗主题变化；悬停和按下时使用正文色图标，分别显示正文色 8% 和 14% 的圆角底色，颜色过渡为 160ms。

输入栏附件按钮可用时使用 primary 色；转发或录音期间禁用时使用 medium 灰色，并保留输入栏按钮统一的禁用透明度。

预览条左侧的编辑与回复图标仅表示当前状态，不可点击；统一使用 medium 灰色和 0.45 透明度，与禁用的附件按钮一致。转发预览左侧为可点击的更换目标按钮，使用 primary 色主转发箭头，右下角叠放 12px 衔尾双箭头角标；角标由 return-up-forward-outline 与 return-down-back-outline 组成，分别向上、向下偏移图标高度的 12.5%，两箭头之间保留空隙，悬停提示“更换转发目标”；点击区域与关闭按钮等大，并共用悬停和按下底色。

消息的手机正文参考 TG iOS，桌面采用 14px 正文以兼顾密度和中文阅读。其组织方式参考 [Signal 桌面字体](https://github.com/signalapp/Signal-Desktop/blob/aee156c662c64dc6cbe5e363325565f5cbd7203a/stylesheets/_mixins.scss)和 [Discord 字号与密度的区分](https://support.discord.com/hc/en-us/articles/207260127-How-to-Change-Discord-Color-Themes-and-Customize-Appearance-Settings)。聊天设置提供五档消息字号，默认保持上述平台字号；字号使用独立分区标题，标题旁显示当前字号或系统默认；滑块下方的双向消息气泡即时预览所选字号与行高，预览区域最小高度 260px；仅消息气泡文字及其行高随选择变化，头像、控件和列表密度保持不变。

布局不统一取整：百分比宽度、文字测量和滚动锚点保留浏览器精度。Ionic 细分隔线及发送图标的视觉偏移允许小数 CSS px。

## 消息布局与 Telegram 参考

作者色使用旧版用户名 hash，用户组颜色直接使用后端字段；不把用户组色与作者色混为一项。

同一台 iPhone、viewport 为 device-width 且无额外页面缩放时，UIKit 的布局点与 CSS px 按 1:1 对应；UIKit pt 不是 CSS 的排版单位 pt。桌面截图还受浏览器缩放与 iPhone 镜像窗口缩放影响，不能直接据此推导字号。

- 气泡引用使用作者半粗、摘要常规；3px 作者色竖边、3px/6px 内边距、4px 圆角，双行默认高度 40px，摘要单行省略。
- 私聊关闭头像和用户名时，消息行左右内边距为 15px，气泡尖角距边缘保留约 7px；菜单预览沿用自身定位。
- 气泡按消息区域实际宽度分段：不超过 500px 时，最大宽度为消息行可用宽度减去 36px；超过 500px 时，最大宽度取可用宽度的 85% 与 560px 中较小值，同时至少预留 36px。显示头像时，固定留白与比例计算均额外扣除 44px 头像列。可用宽度不含消息行左右内边距，短消息按内容收缩，菜单预览沿用自身定宽。气泡内边距为 8px/11px。消息行底部留 4px；同作者连续消息顶部留 4px，新消息组顶部留 8px，因此普通气泡间隔分别为 8px 和 12px。头像距消息区域左右边缘均为 7px，与气泡、桌面回复按钮占用同一网格行并底部对齐，不参与消息行高计算；下方表态占用独立行，不改变头像、尖角和回复按钮的对齐。失败重试图标位于气泡左侧并与消息主体垂直居中，使用 danger 红色、22px 图标和 32×32px 点击区域，与气泡间隔 4px；失败时隐藏桌面回复按钮。时间在末行有空间时靠右，空间不足时另起一行；其向下偏移由正文与时间行高之差决定。“已编辑”、时间与发送状态统一使用气泡文字颜色的 70% 不透明度，随亮暗主题及收发气泡配色变化。已读双勾与确认单勾共用该图标尺寸和对齐。
- 表态独立位于消息主体下方，上下外边距 4px。胶囊造型沿用 main 的 `ReactionPill.module.scss`：胶囊间距 4px、圆角 12px；表情 18.5px，外边距 0.5px/0/0.5px/6px；头像 23px、1px currentColor 边框、重叠 9px，头像组外边距 1.5px。手机与桌面共用这些尺寸，胶囊高度随内容决定；配色使用 Ionic 的 light-shade、primary-tint 和 primary-shade。
- 消息操作面板最大宽度 276px，内边距 6px，每行最多 5 项、按钮高 63px；不足 5 项时保持按钮宽度并随内容收窄。翻页箭头与操作项同尺寸，占第一页末格或第二页第一行末格；行间没有分隔线。表态条与消息预览独立定宽，预览包含 34px 头像和原有 10px 间距。遮罩和内容以 180ms 淡入、120ms 淡出，菜单同时在 0.96 与 1 之间缩放；使用 Ionic 动画，消息本身不缩放。预览保留原消息横向位置，以原内容顶部对齐，新增作者行向上展开，用户名过长时按可用宽度加宽预览以完整显示；表态和操作面板各自保留距屏幕安全区域边缘至少 12px 的空间，不带动头像横移；补出头像列后预览同样保留该间距，靠近边缘时整体横移。竖向避让的位移与 180ms 入场动画同步。表态选择器顶部为 44px 高的同背景栏，左侧 44px 返回按钮内放 22px 箭头，标题“添加表态”相对整个面板居中，不加分隔线。桌面表态选择器优先从加号点击位置下方 8px 展开，四边保留安全区外至少 12px，空间不足时向内调整；窗口缩放和面板尺寸变化时重新定位。手机和平板保持居中。加载阶段预留标题栏与表情区域的总高度。
- 输入栏的附件、文字、贴纸和录音或发送按钮共用一个圆角边框，框内留白 2px、边框 1px；圆角半径为控件半径加 3px，即单行输入栏外部高度的一半，多行输入时保留该半径。录音和发送按钮的占位宽度等于按钮直径，不增加横向留白，单行时按钮右半圆与输入栏右端圆弧同心。录音计时与预览不另加边框。
- 编辑/回复输入栏的上下两部分使用相同的内部控件高度。上排左侧在附件按钮上方显示灰色、不可点击的编辑/回复图标，右侧关闭按钮与下排语音/发送按钮对齐。中间摘要背景保持在输入区范围内，使用 6px 圆角、2px 主题色竖线及 10% 主题色底色；编辑使用自己、回复使用被回复人的名字主题色，并随亮暗主题切换。引用文字默认 12px/14px；尚未加载的回复使用应用主题色。它是紧凑附件栏，不照搬气泡引用的高度。
- 贴纸面板高 260px，网格行高随正方形按钮自然展开，超出面板后纵向滚动；底部包栏固定可见。图片与视频缩略图在 72px 方框内等比居中显示，不裁切。包栏预览使用 24px 图片或静音、循环、内联自动播放的视频；没有可用图片或视频预览时显示默认包图标。
- 输入框文字默认垂直居中，使用正文角色，文字区域与 Ionic 自动增高镜像共用行高。多行输入自动增高至 33vh，超过后仅文字区域纵向滚动，贴纸按钮保持在输入行底部。上下留白由控件高度、边框和行高计算；文字和语音发送飞机均向右偏移 1.5px。
- 待发送及编辑中的附件使用横向滚动的 88×88px 方格，间距 8px，不显示文件名；图片和视频铺满预览，音频使用播放按钮，其余文件显示图标。28px 确定性圆形进度环与重试覆盖在格子内，不配百分比文字；28px 删除按钮位于右上角、内缩 4px。
- 文件拖入输入栏时，覆盖层显示 2px 主题蓝虚线框与 8% 主题色背景，内缩 4px、圆角 12px，120ms 淡入淡出；不占布局空间，不拦截拖放命中。
- 回复按钮按操作系统选择：iOS、iPadOS 与 Android 隐藏按钮，使用左滑回复，图标相对气泡竖直居中，不计下方表态高度；桌面系统在消息旁边预留按钮位置，仅整行 hover 时显示。平台规则与字号一起在全局样式定义，切换触摸模拟或连接触屏不改变按钮占位。
- 只有用户发布的 URL 显示下划线；收到的消息链接使用主题蓝色，自己的蓝色气泡内使用白色。系统消息的用户、目标消息链接和用户 mention 均不显示下划线。
- 普通图片、视频与相册的媒体区域使用不透明中性底色 `--ion-color-medium`，透明像素、比例留白、相册图片间隙与外层媒体容器均使用该底色，单张已知尺寸图片因气泡撑宽产生的两侧留白使用原图模糊副本，原图元素按实际显示矩形铺不透明中性底色，透明像素不透出模糊副本；图文消息媒体下方的 4px 留白放在媒体容器外，与文字区一起保留收发气泡配色，贴纸保持透明，原图透明度不变。
- 气泡背景、图片、视频、相册与文字由同一内容层统一圆角裁切，尾巴在外层单独绘制，避免多层圆角边缘透出底色；顶部有作者或引用、底部有说明文字或话题入口时，媒体与这些内容之间保持直线拼接。纯媒体消息始终不显示尾巴并保留底部圆角，包括带话题入口、正常会话与菜单 overlay 预览中的收发消息。
- 同消息的多张图片/视频按附件顺序拼成相册，自然宽度由 TG 媒体实际占宽按 420px 标准画布换算，气泡随相册收窄，水平与垂直图片间距均为 2px；相册先决定媒体宽度，说明文字在此宽度内换行，不参与气泡的自然宽度计算；窄屏压缩容器时，相册宽度按实际内容宽度缩放，高度独立按 TG 屏幕基准计算，不保留标准画布的空白。媒体布局核心采用 [Telegram Android 13.0.2 的 GroupedMessages.calculate()](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/messenger/MessageObject.java)，保留 2～4 张的专用分支、超宽图通用分支、2～4 行候选枚举、平均比例修正、最小尺寸、评分、候选顺序和 Java float 运算；不另加固定数量模板、长图拆行或评分规则。相册缩略图等比裁剪填满格子，查看器展示完整图片。超过九项只显示九个预览，末格显示 +N，查看器仍包含全部媒体；此预览上限不属于布局算法。单图、贴纸、语音和文件沿用各自尺寸框，贴纸最大 160px；无说明文字的图片或视频气泡不窄于其时间 pill 的两倍宽，窄图由此保留两侧留白。尺寸由元数据与容器宽度确定，缺少尺寸时使用方形占位，资源加载与上传处理不改变初始布局。时间仅在末个可见媒体上显示一次，说明文字位于相册下方。
- 多图相册的说明文字遵循 [Telegram ChatMessageCell 的分组媒体分支](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Cells/ChatMessageCell.java)：先计算分组图片宽度，再据此排版 caption。单张图片的说明文字可影响气泡宽度，沿用单图展示规则。
- Telegram 几何计算与 PWA 渲染分层：`telegram-album-layout.ts` 返回上游标准坐标中的格子宽高及行列跨度；`album-layout.ts` 分别计算不依赖容器测量的自然宽度和填满实测内容宽度的渲染布局，负责水平缩放和水平内部边缘各缩进 1px，内部边缘对齐设备像素，最外侧贴合实际容器宽度而不向下取整；高度沿用 ChatMessageCell 的 `ceil(max(parentWidth, displayHeight) × 0.5 × ph)`，在物理像素中以 Java float 运算逐行取整，跨行图片累加对应行高与行间 2px 间距，间距按设备像素对齐；不使用 Android 的 7dp 行高补偿作为可见间隙。parentWidth 映射消息整行宽度，displayHeight 映射窗口布局视口高度，窗口或消息区域尺寸变化时重新计算；基准不是整个相册的硬高度上限，多行总高度可以超过它。浏览器 `devicePixelRatio` 映射 density，视口短边乘 density 映射 displaySize；收发方向决定行内取整余量落在哪一侧。PWA 没有 TG 的分享按钮预留区，因此调用时 `needShare=false`；Android RecyclerView 的头像、气泡外侧 span 和 caption bookkeeping 不参与媒体几何移植。不同设备参数和平台装饰不保证与 TG 截图逐像素一致。
- 布局对照基准固定到上述 commit；`telegram-album-fixtures.json` 的标准坐标由 `scripts/telegram-album-reference.py` 从该版本 Java 原始表达式生成，测试逐项精确比较行列、整数宽度及 float 高度，不以移植实现自身生成期望值。
- 发送气泡保留应用蓝色与白色文字。媒体预览从顶部开始，按钮悬浮，底部为同消息 gallery。
- 背景色与 main 对齐：会话消息区与完整置顶列表使用 Ionic 默认页面背景（浅色 #fff、深色 #000），接收气泡用 `--ion-background-color-step-100`（浅色 #f0f0f0、深色 #1a1a1a），发送气泡用 `--ion-color-primary`；创建/加入/加好友页（StartChat）、收藏页与资料类页面一样通过 IonContent 的 `color="light"` 设置背景。

引用形状、气泡内边距和消息分组参考 [TG iOS 引用布局](https://github.com/TelegramMessenger/Telegram-iOS/blob/6ad963e5b62d354da79040f388ae2b9132fb17b8/submodules/TelegramUI/Components/Chat/ChatMessageReplyInfoNode/Sources/ChatMessageReplyInfoNode.swift)与[消息布局常量](https://github.com/TelegramMessenger/Telegram-iOS/blob/6ad963e5b62d354da79040f388ae2b9132fb17b8/submodules/TelegramUI/Components/Chat/ChatMessageItemCommon/Sources/ChatMessageItemCommon.swift)。参数表达应用的外观选择，不意味着在所有主题和系统字体设置下与 TG 逐像素一致。

## Markdown 消息

MarkdownBody 使用组件作用域样式，动态元素通过 Angular Renderer2 创建。纯内联内容保留在正文行内，块内容使用受气泡宽度约束的块容器；摘要采用单行内联模式，由调用位置负责省略；置顶、回复引用及输入栏摘要按字体的自然行高度容纳字形，设计行高仅作为最小高度，避免下伸笔画被裁切；聊天列表（含会话及话题草稿）、回复引用、置顶、话题和编辑/回复输入栏摘要保留剧透粒子遮罩，不展示剧透明文，也不允许点击揭示，点击继续交给外层预览操作。列表、代码块及列表项之间不添加固定间距；原文的每个空白行占一行正文行高，遵循[正文换行规则](requirements.md#消息外观与操作)。代码字号为正文的 0.92 倍，围栏代码保留空白并在块内横向滚动。

链接复用消息的链接颜色变量；普通文本和 Markdown 的提及统一使用 0.9em 半粗文字与圆角底色；接收气泡中为主题色文字配 10% 底色，提及自己时为 20%；发送气泡中为白色文字配 18% 半透明白色底，提及自己时为 28%，沿用旧 React 的配色。代码背景从当前文字颜色派生，适配收发气泡与明暗主题。标注支持语言的围栏代码使用 highlight.js 着色，GitHub / GitHub Dark 主题随应用明暗模式切换；未标注或未知语言保留纯文本，行内代码和摘要不做语法高亮。语言按需注册，支持 Bash、C/C++、C#、CSS、Dart、Diff、Go、Java、JavaScript、JSON、Kotlin、Python、Rust、SQL、Swift、TypeScript、HTML/XML 和 YAML；C# 使用 `cs` 或 `csharp` 标记，其余别名需符合字母、数字、下划线、加号或连字符的语言标记格式。

剧透使用 Canvas 独立粒子场，每颗粒子随机方向，以 2–7 CSS px/s 漂移，寿命 1.5–3.5 秒，透明度独立淡入淡出，没有整体循环或折返。密度按遮罩面积每 9 平方 CSS px 一颗计算，每段最多 2500 颗，最多每秒绘制 30 帧。颜色继承正文，画布按设备像素比绘制。

同一段多行剧透共用一个画布，按文字行区域裁剪；相邻行仅在水平重叠处补齐行间留白，粒子跨行共享坐标，不覆盖前后的普通文字。窗口或容器尺寸、字体加载变化后重新测量。首次点击立即揭示文字，不触发内部链接与提及；揭示后恢复操作，点击剧透正文可再次隐藏。离屏、页面隐藏和揭示后停止绘制，消息重建及组件销毁时释放帧回调与观察器。Canvas 不可用时保留静态遮罩并支持直接揭示。

粒子渲染复用已建立的 Canvas 裁剪区域，只有布局或设备像素比变化时重建。出生区域面积缓存，粒子到期后原地复用对象；离屏恢复及再次隐藏时沿用已有粒子状态，避免重新分配与随机重置。

## 转发

来源标签为较小的斜体文字，接收气泡使用 medium 色，发送气泡继承正文色并降低透明度，转发箭头与名称间距 4px；不增加来源头像。聊天记录卡片固定宽 260px，窄屏时不超过气泡可用宽度；前三条预览各占一行，超出宽度的内容以省略号截断。底部与摘要间用主题浅色分隔线；消息总数位于左下角，时间戳和发送状态位于右下角，共用一行并按基线对齐。

多选在消息前预留 30px，圆形标记为 20px，内部使用 14px 的直线 SVG 勾，方形端点与尖角折线，通过网格居中而不依赖文字基线；选中行使用 primary 色的浅背景，不改变气泡内容。底部操作栏左侧显示 danger 色撤回图标，中央显示“n 条消息”，右侧依次显示取消和转发图标；两侧使用等宽区域，使数量始终居中。目标弹窗小屏高度为 90dvh，以自身高度的 0.5 断点打开、可展开至 1，所有断点内容均可滚动，搜索聚焦时展开；768px 起居中显示，宽 600px、高 min(600px, 100dvh - 48px)，隐藏拖动手柄。跨宽度保留同一弹窗、搜索和列表；不按键盘高度改写根页面。行末处理指示区域为 24×24px，列表后的局部读取状态区高 32px。待转发预览位于目标会话输入框上方，复用回复栏的图标列、主题色竖线、浅背景与右侧 ×。预览复用回复栏的两行布局，上方为发送者或参与者摘要，下方为内容摘要或转发条数，每行超出省略；附言使用正常输入框。

聊天记录详情复用会话页的标题栏、消息列表间距、正文与浮动日期标签和连续作者气泡分组；浮动日期沿用会话的重叠避让与停滚淡出行为，固定槽节点常驻；手机占满内容区，桌面位于聊天列表右侧，不使用居中弹窗。标题栏显示返回箭头、24px 的 primary 色文档记录图标与“聊天记录”，图标与标题间距 8px；消息保留双方气泡方向但不显示发送状态。

ChatAvatar 的主头像和话题角标在图片加载期间保留名称文字及主题占位底色；图片成功后覆盖文字并移除占位底色，失败保持文字回退。图片绝对定位于原尺寸内，加载或 URL 变化不改变行高。

通知首页分类使用图标、标题及状态／例外数量两行摘要，行高至少 72px；开关独立位于行右侧，以主题色竖线分隔。分类详情使用独立 inset 列表，例外头像 44px，添加及移除使用 primary 色，删除所有例外使用 danger 色；深浅色均跟随现有主题。
