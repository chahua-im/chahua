# 通知偏好重做计划

在当前 Angular PWA 和 Rust 后端上恢复 `backup/mute` 的账号默认通知偏好与会话例外。参考 `6253e246` 的状态模型，默认值和历史数据迁移以本文确认的规则为准；不移植旧 React 页面或已经重做的提及、回复、表态提醒。起点为 `cef88ea0`。

## 执行约定

- 按下列阶段实施、验证并更新进度。每个阶段形成相对独立的提交。
- 每次提交后立即停止，等待用户确认后才能继续下一阶段。
- 只在本地开发数据库测试写入；不向生产 API、数据库或 S3 写入。

## 业务规则

- 账号分别保存群聊、私聊默认静音，群聊初始为 true，私聊初始为 false；缺少 user_extra 行的账号也采用这组默认值。
- 历史群聊设置全部清除，包括永久／临时静音与通知例外，统一继承群聊默认静音。用户需要手动改变默认值或添加不静音例外。
- 私聊默认不静音，原来的永久静音转为静音例外；原来的临时静音保留到期时间。归档本身抑制普通通知，不依赖静音字段。
- 已归档私聊的永久时间戳按归档附带状态清除，同时清除该会话的通知例外、保留归档。只有未归档私聊的永久静音迁移为静音例外；取消归档后按默认值通知。旧数据无法辨认归档期间的手动永久静音，按用户确认的规则统一处理。
- 会话 `muteOverride` 为三态：null 继承默认，true 始终静音，false 始终通知。
- 尚未到期的 `mutedUntil` 优先；到期后恢复原例外或账号默认。新接口的临时静音不改变例外，持续时间为 1 秒至 7 天。
- 恢复默认、始终静音、始终通知均清除临时静音。有效静音不包含归档；归档、话题订阅、提及和回复仍按各自规则判断通知。
- 保留当前群聊提及／回复、私聊 Web Push 与 APNs 的既有差异。话题按自身订阅和归档判断，不继承父聊天静音。
- 目标行为为归档／取消归档保留通知偏好；旧 DELETE mute 接口继续原子取消静音并取消归档。
- 旧永久静音时间戳保留可读；旧接口必须维护新字段，避免混用客户端后留下矛盾状态。
- 静音不清除未读。列表行、tab、标题、账号角标和推送使用一致的有效静音规则；集合原始未读数仍包含静音会话。
