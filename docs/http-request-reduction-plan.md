# HTTP 请求优化计划

目标：减少重复查询、无关刷新和消息广播引发的 HTTP 扇出，保持实时性、分页位置、提醒目标、隐私与权限边界。

## 执行顺序与提交边界

每个优化项目独立提交；同一协议的后端、生成模型及 PWA 适配一起提交。计划独立提交。

1. [x] Reaction：共享生命周期请求，只有数据变化才追加校准；保留快照确认、跳转目标和离开确认。
2. [x] Push：按账号、设备及订阅内容复用成功注册，合并重复同步，失败可重试。
3. [x] 话题订阅：统一显式及自动订阅事件，携带最终状态；普通消息不作废订阅，未知未订阅话题不刷新列表。
4. [x] 列表：撤回、归档和订阅按受影响对象更新；合并 HTTP/WS 回声，减少已加载分页重读，保留必要校准。
5. [x] 私聊回执：事件携带变更用户和范围，忽略无关事件并共享查询；隐私变化立即清除旧值。
6. [ ] 逐会话状态：增加 WS 范围订阅，推送绝对未读计数和游标；当前列表和会话共享，重连获取完整快照。
7. [ ] 前台恢复：健康连接只校准过期数据，实际重连恢复订阅并补齐数据；缺少可靠事件的数据保留校准。

## 验收

- 请求数量：重复生命周期不重复读取；不变的 Push 订阅不重复注册；无关话题及回执不查询；实时未读不依赖逐项 HTTP。
- 一致性：覆盖延迟响应、事件乱序、请求期间新消息、多设备已读、订阅/归档变化、断线重连和后台恢复。
- 用户体验：保留列表与滚动位置，不清空可展示缓存；reaction 只确认已获取快照；权限和隐私撤销立即生效。
- 测试使用模拟 HTTP/WS，不对生产进行写入。Rust 修改运行 fmt、测试和 Clippy；PWA 修改运行相关测试，完成后运行完整测试。
- 不为减少请求猜测未读增量；不能可靠确定状态时保留校准路径。现有客户端协议尽量保持兼容。

## 后续范围

贴纸组合读取、搜索缓存等低频主动操作暂不纳入执行范围。
